Split :class:`~aiohttp_client_middlewares.RateLimiter` in two, so that neither
half has to describe a contract it does not keep.

:class:`~aiohttp_client_middlewares.RateLimiter` now declares the async
``wait()`` and ``clone()``. A limiter that reserves its slot over the network
implements those two and is done; it no longer has to stub out an ``acquire()``
that is never called.

Algorithms that reserve a slot without awaiting subclass the new
:class:`~aiohttp_client_middlewares.SyncRateLimiter`, which supplies ``wait()``
and asks for ``acquire()`` instead. ``release()`` moved there with it, and so
did the guarantee that slots are granted in arrival order, which only ever held
for these. :class:`~aiohttp_client_middlewares.TokenBucket` is one of them and
is otherwise unchanged.

To upgrade, a limiter that implements ``acquire()`` changes its base class to
``SyncRateLimiter``; leaving it on ``RateLimiter`` now raises ``TypeError`` at
instantiation, for the abstract ``wait()`` it does not define. Code that calls
or overrides ``release()`` through a ``RateLimiter``-typed reference needs the
narrower type. ``RateLimitMiddleware`` accepts either and is unaffected
-- by :user:`rodrigobnogueira`.
