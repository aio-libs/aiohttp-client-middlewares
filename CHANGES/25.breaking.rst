Made :meth:`~aiohttp_client_middlewares.RateLimiter.acquire` async so rate
limiters may reserve slots through Redis, a database, or another I/O-backed
service without replacing the shared wait logic.

:class:`~aiohttp_client_middlewares.RateLimiter` continues to supply
``wait()``, which now charges acquisition time against the timeout before
sleeping out the returned delay. It also continues to own timeout and
post-reservation cancellation cleanup through ``release()``. An ``acquire()``
implementation is responsible for leaving no reservation behind if it is
cancelled or raises before returning.

To upgrade, change a synchronous ``def acquire(self)`` implementation to
``async def acquire(self)`` and await any direct calls to it. An implementation
that needs no I/O can omit ``await`` internally; it then retains atomic
arrival-order reservation on one event loop, as
:class:`~aiohttp_client_middlewares.TokenBucket` does
-- by :user:`rodrigobnogueira`.
